# 以修复后的朴素实现为参考：逐算子对比

日期：2026-11-03，Asia/Hong_Kong。本轮仅用GPU0、仅诊断；生产模型和公共算子保持原样，没有提交Git。

## 本轮结论

选HumanEval/61，123个输入token。修复后的朴素版两次64/64；原生Mellum/Qwen3-MoE骨干+torch专家、BF16路由、RNE关闭的版本两次5/64，均逐值复现各自之前的结果。本轮直接读取朴素实现的中间结果作数值参考，未运行HF模型。

独立差异来源已定位到norm与融合残差、合并QKV、部分RoPE路径、attention，以及路由排列造成的专家输入行排列。KV读写、o_proj、router线性层、LM head和固定路由排列的专家内部计算在本轮控制实验中一致。

这些结果说明存在多处数值约定差异，不表示每处都是结构错误，也没有证明其中一个单独足以造成整条输出分叉。本轮没有直接更换生产算子或启用RNE。

## 实验范围和控制

- 参考：当前修复后的`MellumNaiveForCausalLM`，已经通过本地公开200条token一致性检查。
- 对照：`MellumTorchExpertsForCausalLM`，保留原生骨干、attention、norm、路由和加载器，torch专家、BF16路由，RNE关闭。本轮不将原生融合专家的不稳定性掺入对照。
- 两侧均单卡、BF16权重/KV、eager、编译等级0，MTP/TBO/prefix cache关闭。
- 对两侧前6次预测的全部28层记录实际输出。这6次预测的输入前缀完全相同，输出第6次才分叉。
- 在prefill和第6次预测，逐层用朴素版的相同输入重放，共56组。另记录普通生成中的全部6步KV读写，共336组（2个实现×6步×28层）。
- 同输入重放之前，先用朴素自身及原生自身数据验证重放：attention 56/56控制通过，专家内部拆解56/56控制通过；两侧RoPE的自身重放也全部通过。
- 朴素版全部5631个检查点源tensor到311个目标参数、原生torch专家版到255个目标参数逐值核对通过。

本样本最大KV长度128，小于滑窗1024。这里不能用输出差异推断SWA窗口边界错误，也不能用这个短样本替代16k配对或HumanEval功能测试。

## RoPE：SWA和全局层的结果不同

本轮捕获实际`rope_cache`返回的Q/K，覆盖SWA融合路径，并防止多个层共享同一个rotary模块时互相覆盖记录。

| 路径 | Q精确一致 | K精确一致 | Q/K最大相对L2 |
| --- | ---: | ---: | --- |
| prefill，21个SWA层 | 12/21 | 19/21 | 0.0000935% / 0.0002664% |
| 第6步decode，21个SWA层 | 21/21 | 21/21 | 0 / 0 |
| prefill，7个全局层 | 0/7 | 0/7 | 0.217612% / 0.136159% |
| 第6步decode，7个全局层 | 0/7 | 0/7 | 0.234076% / 0.223156% |

因此本轮较明显的独立旋转差异集中在全局层。表格不能单独证明具体是cos/sin精度、乘加舍入或哪条底层指令导致；进一步修正应在这些层做受控验证。

旧追踪的原生RoPE子阶段存在问题：21个SWA层没有通过rotary模块hook捕获，7个全局层共享模块时记录被覆盖。已在相关结果目录添加`rope_trace_instrumentation_caveat.json`。旧的原生RoPE张量比较，以及从这些字段选出的“首个超过1%阶段”，不再作为结论依据。norm、QKV、真实层边界hidden及最终logits是独立记录，未因这次追踪修正被推翻。

## Attention：已隔离实际decode路径

每一组都用小型独立KV缓存重放，K/V写入、读取逐值核对；再用原生自身的Q与K/V验证输出能复现实际生成。全部56组通过后，才换成朴素版Q与完整K/V作比较。

| 阶段 | 实际原生后端 | 精确一致 | 最大相对L2 |
| --- | --- | ---: | ---: |
| prefill，SWA层 | prefill_attention | 0/21 | 0.064460% |
| prefill，全局层 | prefill_attention | 0/7 | 0.055488% |
| decode，SWA层 | paged_attention_triton，实际调用pa_decode_gluon | 0/21 | 0.085205% |
| decode，全局层 | paged_attention_asm | 0/7 | 0.080421% |

这次decode结果来自实际分页后端的独立重放，不是用prefill函数模拟decode。相同Q/K/V和可见范围下仍有差异，支持继续检查attention数值实现；具体内部舍入或归约方式尚未完全隔离。

## 专家内部：固定路由后全部一致

两侧输入hidden、专家权重、专家ID及BF16路由权重完全相同时，逐项检查：

| 专家内部操作 | 精确一致 |
| --- | ---: |
| gate/up GEMM | 56/56 |
| gate的SiLU | 56/56 |
| SiLU(gate) × up | 56/56 |
| down GEMM | 56/56 |
| 乘BF16路由权重 | 56/56 |
| 按专家顺序index_add累加后的完整输出 | 56/56 |

使用原生路由时，56组的专家集合及BF16 dense权重仍相同，但有35组的有序ID列表不同。专家代码按“路由slot、token”收集输入，slot排列改变会改变每个专家GEMM的输入行排列。

将结果按token重新对齐后，差异已能在gate/up GEMM观察到；固定同一路由排列则所有内部操作一致。这是本轮模型进程内、通过自身控制的证据，补齐了之前独立route-order探针无法复现参考的缺口。decode每个专家仅处理当前单个token，本轮28层完整专家输出全部一致；prefill有11/28层的最终专家输出不同。

这种排列差异引起的BF16数值变化不能直接称为专家公式、权重映射或SiLU独立错误。它也没有被证明是本条首次输出分叉的唯一原因。
