# GPU0：HumanEval/61逐层Logits与Hidden States对比

日期：2026-11-03，Asia/Hong_Kong。层编号从0开始。本轮仅诊断，没有修改模型或AITER算子，没有Git提交。

**已定位到具体数值兼容性问题：当前原生norm/融合残差使用的BF16转换默认截断（RTZ），与HF的舍入路径不同。差异从第0层RMSNorm开始，进入Hidden States后经过28层传播，最终翻转候选token排名。** 本轮没有实施RNE修复，不能据此声称只改一个设置即可达到90%。

## 样本和对齐方式

从用户已停止的BF16路由全量测试的96条已完成样本中，按“同位置一致token最少、连续一致前缀最短、ID字典序”选择HumanEval/61。输入123 token，生成64 token，仅5/64一致；前5个输出相同，第6个首次分叉。它是这96条中的最差样本，不是未完成200条的全局最差。

GPU0依次运行HF与当前版本。HF为原生Transformers 5.10.1、BF16、SDPA、eager experts；ATOM为原生骨干+torch专家、BF16路由权重、BF16 KV、eager/level0、MTP和prefix cache关闭。捕获前6次预测全部28层，逐步检查输入ID及此前输出前缀相同。ATOM两次输出相同，并复现停止测试中的结果；HF复现冻结参考。

## Hidden States和每层logits的定义

- HF使用各层真实输出。原生骨干返回branch/residual双流，使用下一层norm实际输出的residual作为上一层完整状态；第27层使用最终norm输出的residual。没有用额外的torch加法伪造原生层边界。
- 每个位置保留完整Hidden States。下方“第6步”是单个decode查询；prefill另外记录全部123个位置。
- 中间层没有模型原生输出的词表logits。本报告将各层最后一个查询位置的状态，统一送入**同一份checkpoint最终norm和LM head，以FP32计算**，得到诊断用logit lens。两侧投影方式完全相同，用于观察状态差异。
- 模型真实最终logits另行捕获，不将FP32诊断投影当作BF16模型的真实输出或验收分数。

## 更具体的精度原因：BF16截断

已检查当前调用链：`ATOM RMSNorm -> aiter.rmsnorm2d_fwd -> rmsnorm -> module_rmsnorm_quant`。

源码证据：

- `/app/aiter-test/aiter/ops/rmsnorm.py`：当前维度2304/128、未开启model-sensitive模式时，走`rmsnorm/add_rmsnorm`入口。
- `/app/aiter-test/aiter/jit/optCompilerConfig.json`：`module_rmsnorm_quant`默认传入`OPUS_FP32_to_BF16_DEFAULT=2`；当前没有环境变量覆盖。
- `/app/aiter-test/csrc/include/opus/opus.hpp`：默认值2标注为truncate；对应实现直接把FP32位模式右移16位。该gfx942卡走此分支。

共享输入的独立实测：

| 检查 | 结果 |
| --- | --- |
| HF的norm公式与捕获HF输出 | 逐元素一致 |
| 归一化及乘gamma后直接截断一次，与原生RMSNorm | 99.998939%元素一致；最大残差0.00001526，相对L2约0.0005025% |
| 原生融合残差与FP32相加后截断到BF16 | 逐元素完全一致 |
| 原生融合残差与HF式舍入到最近BF16的加法 | 不一致，最大差0.03125 |

RMSNorm仍有约3个元素不能被上述简化公式完全复现，可能涉及归约/浮点运算顺序，尚未单独拆分。不把99.998939%写成100%。这些证据确认了转换模式差异；它不等同于参数权重被错误加载成其他dtype。

本轮没有设置新的OPUS编译宏、重编译AITER或替换norm；下一步需要以受控方式验证RNE数值约定的影响。
