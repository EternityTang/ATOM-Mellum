# HumanEval/66：RNE后退化的逐层诊断

日期：2026-11-03，Asia/Hong_Kong。仅使用GPU0，HF与三个ATOM配置依次运行；GPU1的独立朴素版全量任务未被停止、重启或用于本轮诊断。本轮没有修改生产模型、算子、权重、参考或依赖，没有提交Git。

## 直接结论

HumanEval/66已稳定复现：原生RTZ路径64/64，native顺序RNE为5/64，HF顺序RNE为39/64。native RNE的隐藏状态比RTZ更接近HF，但第6次预测中两个接近候选词的相对分数翻转，输出从`write`变成`complete`。随后两侧输入不同，后续同位置token大量不一致。

因此，64/64不能证明原路径的每层数值等于HF，5/64也不意味着模型权重损坏或代码功能正确率只有5/64。这里首次分叉发生在thinking文字；本轮没有进行HumanEval功能判分。

当前RNE实现只改变了部分数值约定，native顺序仍不同于HF；即便norm使用HF顺序，合并QKV与原生attention也会独立留下差异。没有证据把第6个token的翻转完全归因于单个QKV内核、attention内核或某层路由。已完成的观察与隔离结果如下。

## 配置与复现

- 固定公开数据中的HumanEval/66，输入144 token，各生成64 token，greedy、ignore_eos。
- HF：Transformers 5.10.1，BF16，SDPA attention，eager experts；新输出逐值复现冻结参考。
- ATOM：单卡，原生Mellum/Qwen3-MoE骨干+torch专家，BF16路由权重，BF16 KV，eager/level0，MTP与prefix cache关闭。
- 三组ATOM各运行两次，均稳定且逐值复现各自之前固定10条的输出。每组全部5631个检查点源tensor到255个目标参数逐值核对通过。

| norm路径 | 同位置token一致 | 连续相同前缀 | 首个输出分叉 | 两次重复 |
| --- | ---: | ---: | --- | --- |
| 原生AITER RTZ | 64/64 | 64 | 本轮64个中无 | 相同 |
| RNE，native顺序 | 5/64 | 5 | 第6个，write→complete | 相同 |

另保存每层状态经过同一FP32最终norm与LM head的诊断投影，shape为`[4,6,28,98304]`（HF、RTZ、native RNE、HF顺序RNE）。真实最终BF16 logits另外保存，不能混用两类结果。

## 第6次预测：分数怎样翻转

共同前缀为：

```text
<think>
We need to
```

| 实现 | `write`，ID2468 | `complete`，ID3559 | 实际greedy输出 |
| --- | ---: | ---: | --- |
| HF | 31.000 | 31.000 | write，取较小ID |
| 原生RTZ | 30.750 | 30.625 | write |
| RNE native | 30.875 | 31.000 | complete |
| RNE HF顺序 | 31.000 | 31.000 | write，取较小ID |

此处分数约31，BF16相邻数间距为0.125。native RNE下，`write`比`complete`低一个BF16间距，因此Sampler选择complete符合argmax。前6次的各组实际输出均已与当次logits argmax核对，不是Sampler随机选择或不遵守greedy。

RNE让write的分数由30.750更接近HF的31.000，同时complete也从30.625变到31.000；这两项改变对排名的作用不同。token一致率取决于排名，不能只看单个logit或隐藏状态的整体误差是否变小。

## 逐层状态说明

| 第6次预测的位置 | RTZ相对HF的L2误差 | native RNE | HF顺序RNE |
| --- | ---: | ---: | ---: |
| 第0层input norm | 0.386083% | 0.258326% | 0% |
| 第0层attention context | 0.487698% | 0.253226% | 0.046258% |
| 第0层真实边界hidden | 1.011465% | 0.123250% | 0.061515% |
| 第7层真实边界hidden | 2.156630% | 1.330005% | 0.802290% |
| 第27层真实边界hidden | 5.398695% | 4.249606% | 3.692641% |

native RNE确实降低了这些位置的误差，仍未保住第6个token的排名。它在第0层input norm就与HF不同，因为仍先在FP32完成RMS/gamma及未舍入残差的处理，HF有中间BF16舍入。RNE HF顺序下，第0层input norm与HF相同，首次数值差异移动到QKV投影。

第6次预测的最后一个查询token，RTZ和native RNE首次出现专家集合不同的层均为第11层（从0计数），HF顺序RNE为第10层。两种版本即便首次路由集合分叉层相同，后续各层状态与路由也不相同；不能据此认定它们的误差相同或第11层就是唯一根因。

## 同输入重放：哪些部分独立存在差异

使用HF捕获的相同输入，隔离prefill与decode第6步的全部28层，共56组。不是把已经分叉的两个模型输出直接当作组件输入。

| 隔离项 | 与HF逐值一致 | 已确认的含义 |
| --- | ---: | --- |
| 将原权重分开执行Q/K/V三个F.linear | 56/56 | HF权重、输入和分开投影在此处可复现 |
| 原生合并QKV | 14/56 | 同输入下合并计算仍有微小差异 |
| 原生合并QKV对照torch合并F.linear | 56/56 | 差异可由合并矩阵的计算形式复现，并非只有ATOM的线性封装才有 |
| attention输出后的o_proj | 56/56 | 固定相同attention context时复现HF |
| router gate线性层 | 56/56 | 固定相同post norm输入时复现HF |
| 原生路由转BF16后的dense专家权重 | 56/56 | 相同router logits下，每个专家对应的路由权重逐值一致 |
| torch专家，固定HF的输入、专家ID及权重 | 56/56 | 本轮原始模型进程内可复现HF专家输出 |
| torch专家，使用原生路由返回的排列 | 43/56 | 13个prefill层仍有微小差异，不能仅凭dense权重相同认定整段专家计算完全对齐 |
| 原生prefill attention，固定HF Q/K/V | 0/28 | 排除上游QKV差异后，原生attention本身仍与HF SDPA有差异 |

合并QKV的最大相对L2差为0.0166445%；固定Q/K/V的原生prefill attention最大为0.0656448%。后者只检验prefill，不能外推为实际分页decode内核的隔离结果。

原生路由排列下的13个专家输出差异，最大相对L2约0.0110573%。补充的独立进程route-order探针没有复现HF专家参考，已标为`inconclusive`并排除出因果结论；目前尚不能断言这些差异只由专家顺序、GEMM行排列或某个具体内核机制导致。主模型进程内的上述56组记录独立完成、有效保留。
