# Mellum 解码中跨层复用 RoPE 与 KV 写入地址

2026-11-04，单张 MI308X（物理 GPU1）。本轮从 `mixed_packed` 精度候选和 `paged_grouped` 速度候选出发，改动 decode 中可重复使用的中间结果，保留两条路径各自的 attention 与专家计算。

## 同服务分项测量

| decode 路径 | 新开关 | 输出 token/s | 相对本轮父版本 | 固定 10 条对 HF | 固定长输入对父版本 |
|---|---|---:|---:|---:|---:|
| 精度 | 父版本 | 216.69 | 基准 | 640/640 | 512/512 |
| 精度 | 单独跨层复用 RoPE | 228.85 | +5.6% | 640/640 | 512/512 |
| 精度 | 单独复用 Torch 写入地址 | 215.39 | −0.6% | 640/640 | 512/512 |
| 精度 | 单独使用 AITER 写 KV | 214.10 | −1.2% | 640/640 | 512/512 |
| 精度 | RoPE 复用＋AITER 写 KV | **232.06** | **+7.1%** | **640/640** | **512/512** |
| 速度 | 父版本 | 425.75 | 基准 | 356/640 | 512/512 |
| 速度 | RoPE 复用＋AITER 写 KV | **555.45** | **+30.5%** | **356/640** | **512/512** |

短输入的速度候选与父版本的 640 个 token 全部相同，均为 4/10 条对 HF 完整一致。精度候选为 10/10。长输入对单请求 HF 分别为精度版 329/512、速度版 345/512，各自与本轮和上一轮的固定批次父版本逐位对齐。以上是 greedy token ID 对照。本轮未做新候选的 200 条全量回归或正式 A/C 评测。

单独切换写 KV 的两个版本均只测一次，与对照相差约 1%，没有观察到稳定的独立收益。速度路径本轮测了组合开关，在该路径上的总收益不能拆成两个单项的贡献。

## 实现与正确性检查

- **RoPE**。28 层共用一个 RoPE 模块。同一模型前向的 positions、设备、精度相同，首次调用仍按原实现算出全局层和滑窗层各自的 cos/sin，后续层取本步结果。新前向清空缓存。组件用同一张量原地改变位置，包括滑窗边界与长位置，再次与原公式逐值对照。两次 decode 和一次 prefill 中原函数分别被调用 1、1、28 次。
- **跨层复用写入地址**。在每步首次写入前，提取有效行、物理页号及页内偏移。28 层使用同一组地址，各写入本层的 K、V。读 KV 与 SDPA 算法沿用父版本。
- **专用 KV 写入**。另一条路径使用镜像内已提供的 AITER `reshape_and_cache`。同一步复用连续 int64 slot 向量，内核跳过负 slot，直接把 BF16 K、V 写到原布局。写入不做量化。地址复用与专用写入是同一操作的两个备选实现。组合版使用 RoPE 复用和专用写入。
- 组件覆盖 1、7、32 个 token，int32/int64 slot，无、部分与全 padding，物理页打乱和非连续源张量。18 组写入后的完整 K/V 页与原始 Torch 写法逐值相同。
- 端到端用已冻结的 10 条困难 prompt，各生成 64 个 token。逐位置与原始 HF token ID 以及相应父版本比对。另将 32 条各 1024-token 输入用固定顺序一次性交给离线引擎，各生成 16 token，共 512 个位置，首尾重复控制组。

## 性能测试口径

服务器以 BF16、单卡 eager、编译等级 0 运行，关闭 prefix cache 和 MTP。使用与先前 vLLM 测试相同的 32 条唯一输入，并发提交，各 1024 输入 token。先预热 4 输出，正式每条生成 256 token，核对每条 usage，按 8192 除以整批耗时计算输出吞吐。消融实验在同一服务切换开关，静态入口另外启动服务复核。旧版 vLLM 参考为 751.92 输出 token/s，固定 10 条对 HF 为 346/640。

## 服务和文件

独立服务入口复测得到精度候选 **234.87 token/s**、速度候选 **542.88 token/s**。随后从原入口复测精度父版本为 **211.89 token/s**。独立入口的精度组对照提升 **10.8%**，TPOT P50 从 140.06 降到 125.26 ms。同服务分项测量得到的提升为 7.1%，两个结果分别报告。速度候选独立入口的结果达到此前同场景 vLLM 吞吐的 **72.2%**。两种新候选的首 token P50 仍约 2.94 s，vLLM 约 1.22 s。

满批解码采用上轮相同的分模块同流 event 计时，取 5 步中位数。详细算子次数来自另一批的第 8 个满批解码步。

| 路径 | attention 毫秒/步，父版 → 新版 | attention GPU kernel 数，父版 → 新版 | 新版 MoE 毫秒/步 |
|---|---:|---:|---:|
| 精度 | 64.72 → 49.76 | 2,763 → 1,745 | 60.25 |
| 速度 | 39.75 → 23.46 | 1,932 → 914 | 18.61 |

两条新路径在 attention 内的 sin 和 cos 各由 56 次降为 2 次，`aten::nonzero` 消失，每步各发出 28 次 AITER 专用写入 kernel。精度候选仍按页索引读 KV 并用 SDPA，仍逐专家执行 PyTorch GEMM，因此相同的跨层复用改动在两条路径上体现为不同的端到端收益。旧 vLLM 参照的 attention / MoE 分别为 18.19 / 15.23 ms/步。这里比较的是相同负载下的模块耗时，多个开关之间的交互不能仅用单个 kernel 的 GPU 耗时推算。
