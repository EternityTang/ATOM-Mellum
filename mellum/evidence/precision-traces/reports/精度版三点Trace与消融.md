# 精度版逐阶段 Trace 和优化点选择

本轮目标是从精度版已有候选及新增替代方案中挑出有证据支持的三个点。验证口径为冻结 Torch 2.10、同一份 HF eager 逐条参考。固定 32 条真实变长 prompt，每条生成 128 token，核对前 64。对照和优化共享直接分页 KV、cap8 投影/专家、原有模型与调度。这个共同底座是内部消融对照。

## 第一轮：逐阶段观察实际工作量

每个阶段抓同一位置的一步真实 decode，批大小32。Trace 用于比较事件数和算子分布。端到端吞吐取独立的无 profiler 运行，包含 prefill，预热排除。Trace 期间另一张卡可能有独立速度实验，因此不以 trace 累计时长比较吞吐。

| 阶段 | GPU kernel | 直接 hipLaunchKernel | 图回放 | softmax 调用 | BMM 调用 |
|---|---:|---:|---:|---:|---:|
| s0 | 42,340 | 37,432 | 0 | 924 | 1,792 |
| s1 | 42,340 | 6,403 | 253 | 924 | 1,792 |
| s2 | 16,027 | 6,403 | 253 | 924 | 1,792 |
| s3 | 12,877 | 3,253 | 253 | 378 | 1,792 |
| legacy0 | 45,640 | 38,968 | 0 | 924 | 1,792 |
| legacy1 | 45,640 | 7,939 | 253 | 924 | 1,792 |
| legacy2 | 19,327 | 7,939 | 253 | 924 | 1,792 |

1. **局部 HIP Graph。** S0 的直接 launch 数很高。关闭 graph 的对照仍按同样的桶和矩阵形状计算。S1 保留 GPU kernel 数，通过图回放减少主机发起次数。此点与原生速度版的整步 graph 是不同配置。
2. **Norm 逐元素合批。** S1 已压低主机派发，但图内仍有大量逐请求小算子。把残差加、平方、缩放等逐元素计算合批，保留逐请求均值和 BF16/FP32 边界。S2 图回放数相同，GPU kernel 数下降。之前整块 Norm 合批或直接换 Triton Norm 都掉过精度，因此保留原归约。
3. **滑窗 softmax 合批。** S2 剩余的热点包括 QK/PV BMM、分页 KV gather 和专家投影。对等 KV 长度的相邻请求只合批中间运算及 softmax。S3 的 softmax 调用减少，BMM 次数保持。之前单独合批 PV 在固定 32 条仅 1127/2048，复现了两次 BMM 都合批的分叉，因此保留原 BMM 形状。

## 第二轮：用 prefill trace 寻找可能替换第三点的方案

S3 另抓一个五请求 prefill 批次。专家 F.linear 和 attention 都重，且有 35,665 个归因于 nonzero 的 GPU kernel、7,789 次 hipMemcpyWithStream。沿源码追到每专家一次 where 和按专家逐个派发。新候选在 prefill 一次稳定排序路由，保留 slot-major 行序、完整专家 GEMM 形状、加权和原 index_add 顺序。只在 prefill 打开。候选从 S2 起步，和 S3 的滑窗方案竞争同一个名额。

替代 prefill trace 的实际批大小为 5，GPU kernel 62,414，hipMemcpyWithStream 1,132。原 prefill 批次对应 109,293 个 kernel。

空闲复核链的局部图增量为 **+35.05%**，Norm 为 **+19.78%**，相邻滑窗合批为 **+8.75%**。这些是相邻配置差值，基线和后续各阶段使用相同输入、输出长度及卡。

相同长度的非相邻请求合并和跨层复用零 mask 各独立测试。前者以 Q/输出重排换更少的组，后者以小型 per-step 缓存换重复分配。直接 KV 与投影 cap8 的对照分别测 S2 关直接 KV 和 S3 降 cap1。首次启动脚本覆盖了传入变量，运行时审计显示两条仍为 direct/cap8，首轮保留日志并作废。修正 launcher 后两条都按 runtime.json 验证开关已生效。

已排除的历史方向也纳入记录。QKV 完全融合固定 10 条 232/640，整块 Torch Norm 合批 564/640，PV 合批 1127/2048。上一轮路由准备融合短测 +1.37%，Torch grouped GEMM -2.39%，Attention BMM 直接写入 -1.11%。本轮因此把 MoE 试验移到 trace 显示开销更大的 prefill，而非重复改 decode 专家算术。


滑窗和 Prefill 路由在输出128时接近，补跑同32条各输出256。滑窗 **107.185 tok/s**，Prefill 路由 **102.140 tok/s**，前64匹配分别 100.00% 和 100.00%。此复核每项一轮。Prefill 路由保留为备选。

开关生效后，cap8 相对 cap1 在 S3 下约 **+13.82%**，cap1 最低 token 匹配 100.00%。

## 最终排序：将直接 KV 从底座拆出来计点

开关核验后的直接 KV 边际收益为 **+21.20%**，高于滑窗的 **+8.75%**。于是重建旧 KV 的共同起点，单独补抓未开图、开启图、再加 Norm 的三个 trace。对照中的 cap8 投影和专家配置固定。末级复用原 S2 采样，和 legacy2 的 GPU 分组形状对齐。

| 累加阶段 | 同卡吞吐 tok/s | 相邻提升 | 前64 token |
|---|---:|---:|---:|
| 旧 KV 共同底座 | 44.888 | — | 100.00% |
| +局部 HIP Graph | 59.215 | +31.92% | 100.00% |
| +Norm 逐元素合批 | 63.679 | +7.54% | 100.00% |
| +直接分页 KV 读取 | 77.181 | +21.20% | 100.00% |

第三点的 trace 直接比较 legacy2 与 S2。GPU kernel 数 **19,327 → 16,027**，PV/QK BMM **1792 → 1792**。直接按页读并生成现有 attention 需要的 KV 布局，保留逐请求注意力计算。

以上链固定 cap8，用于看每次改动的作用和交互。旧 KV 路径的 Norm 增量较小，启用直接 KV 后 Norm 的增量更大。因此另外用三点预算比较组合吞吐。

对应开关为 PRECISION_LOCAL_GRAPH、PRECISION_NORM 和 KV_MODE。滑窗及 Prefill 的对照开关分别为 ATTENTION_MODE 和 PRECISION_PREFILL_PACK。各阶段 trace、原始 token、测试脚本和本轮尝试快照随证据保存。
